# 07｜字符级 bigram：先把文本和评估做对

从仓库根目录运行，依赖安装见[首页](../README.md)。本课无下载，默认 CPU 单线程、固定种子，从随机权重训练：

```bash
python 07-character-language-model/train.py --steps 200 --output-dir artifacts/07
python 09-inference/generate.py --checkpoint artifacts/07/best.pt --prompt 清晨 --seed 17 --max-new-tokens 60
```

先试跑 `--steps 10` 检查环境，再使用完整预算。可调整 `--block-size 32 --batch-size 8 --learning-rate 0.1 --eval-every 25 --seed 17`。步数是优化器更新次数，训练随机抽取批次并允许重叠窗口；不是 epoch，也不保证每个训练窗口都被抽到。

## 数据、形状与标签

阅读[原创语料说明](../data/text/README.md)。24 篇短文属于 12 个场景来源组；固定划分种子 17，8 组训练、2 组验证、2 组测试，同组不分家。训练随机种子变化不会改动数据划分。词表只从训练正文建立，验证/测试未见字符编码为 `<unk>`（ID 0），不丢弃；启动输出和 `metrics.json` 都报告未知字符数与比例。高未知率会限制可解释性，不能为了好看的分数向词表添加测试字符。

输入 `清 晨 有 风` 的标签必须是 `晨 有 风 。`。每个训练窗口在一篇文档内取 `T+1` 个字符，再切成 `x=tokens[:-1]`、`y=tokens[1:]`。形状为 `x=[B,T]`、`y=[B,T]`、`logits=[B,T,V]`；交叉熵将前两维展平为 `[B*T,V]` 和 `[B*T]`。程序打印第一个窗口的输入/标签 ID 与初始预测概率前三项，ID 对照检查点中的 `vocab`。

`nn.Embedding(V,V)` 是可学习概率表的 logits，每行对应一个当前字符。softmax 后得到下一字符分布；例如 `p(晨 | 清)`。虽然批次包含 32 个位置，bigram 每个位置只看当前一个字符，不能利用更早上下文。这里的 embedding 输出直接用作分类 logits，还没有 Transformer 的隐藏向量表示。交叉熵接收原始 logits，不要先手动 softmax 再喂给它。

## 怎样读结果

每 25 步完整计算训练/验证指标，以验证平均负对数似然最低的检查点保存到 `best.pt`，初始模型也参与选择。训练完成后重载该权重，只对测试集完整计分一次。`metrics.json` 有初始及后续训练/验证曲线点、选择步数、测试结果、参数量、耗时、环境和数据版本；可自行画出 `history` 曲线，不预设损失一定下降或胜过下一课。

评估规则在 07/08 完全共用：每篇文档从开头按 `block_size` 依次取块，标签范围互不重叠，最后不足一块也参与。每篇第一字符只作输入，其余每个字符恰好计一次；块之间只共享边界的一个输入字符，不传递更早隐藏上下文；不跨文章。这是方便核对的小型评估协议，不等于对每个位置使用最大滑动历史。两模型比较时必须用相同上下文长度、词表、语料哈希与划分。有效计分 token 数应相同。

平均 NLL = 所有 target 的交叉熵总和 / target 数；使用自然对数，所以 `PPL=exp(NLL)`，越低表示对这份编码后文本预测越好。最后短块按 token 数加权，不能直接平均块平均值。`<unk>` 也是评估 target，训练语料中没有未知字符；未知率较高时该指标并不能充分衡量原始字符恢复能力。生成样例没有测试分数的含义，也不能拿“读起来顺”替代定量评估。

## 练习与边界

1. 打印前三个训练窗口，用词表解码，并手工检查标签左移一位；尝试故意错位，观察模型会学成什么。
2. 从某个输入字符的一行 logits 手算 softmax 与一个 target 的负对数概率，对照交叉熵。
3. 只改变学习率，比较初始/最终训练与验证损失；如训练下降而验证上升，检查未知率和过拟合。
4. 用同一提示和种子生成，记录重复、不通顺或 `<unk>` 等失败。bigram 只能学相邻字符关系，不能据此推断通用对话能力。
